# BugCam

**“我这里报错了”之后，给对方一段能看懂的现场。**

点了什么？哪一步出错？再点一次还会发生吗？
BugCam 把浏览器操作、当时的画面和异常调用栈放在同一条时间线上，再另开浏览器复现一次。讨论缺陷时，大家可以对着同一个现场说话。

![故障回放台：浏览器现场、操作时间线与右侧错误详情](docs/images/replay-workspace.png)

### 把一句报错，展开成一段经过

- **回看发生了什么**：逐步切换截图，定位异常前的那次点击。
- **看清为什么报错**：页面异常和调用栈与对应画面放在一起。
- **再跑一次核对**：独立浏览器重新执行，匹配到相同异常才确认复现。

适合开发者和测试同学演示缺陷取证流程。**当前只操作仓库自带的 Parcel 示例**，其中导出错误是故意预置的；浏览器执行、截图、录像和复现检测都是真实发生的。

### 在本机打开

准备 **Node.js 24 LTS** 与 npm（也支持 22.12+ 的 22 系列及 26+；不支持 23/25），然后运行：

```sh
git clone https://github.com/shenyangs/bug-cam.git
cd bug-cam
npm run setup
npm run doctor
npm run dev
```

浏览器打开 [http://127.0.0.1:4204](http://127.0.0.1:4204)，终端保持运行；结束时按 Ctrl+C。首次 setup 会联网安装依赖与测试浏览器，下载时间取决于网络。安装问题见 [使用手册](docs/usage.md)。

### 找到那次导出失败

1. 点击 **开始扫描**。Chromium 会依次操作预览、保存和导出。
2. 在下方时间线选中导出步骤，查看现场截图与“报告数据未定义”的异常。
3. 点击 **复现异常**，等待新浏览器核对；再点 **观看复现录像**，回看执行过程。

![独立复现完成：两次执行证据、异常调用栈与实际步骤时间线](docs/images/replay-details.png)

一次运行的截图、WebM 录像和 `result.json` 会保存在 `artifacts/hunts/<运行 ID>/`。需要继续排查时，可以直接查看这些文件。

### 现在适合演示什么

它能演示“操作 → 报错 → 留证 → 独立复现”的过程，还不能扫描你的生产网站，也没有 AI 推理。最多检查 8 个符合规则的控件，只支持点击，同一时间运行一个任务。

当前只把匹配的页面异常算作确认缺陷；普通 `console.error`、请求失败或业务结果不对，不在确认范围。重启会清空页面中的运行索引，已保存的文件仍在本地。

### 想继续看代码或验证结果

本地构建、单元测试、浏览器流程和演示录屏已经在 macOS 通过；README 配图来自实际运行的应用。Windows / Linux 实机与全新机器完整安装尚未验证。所有服务仅监听本机，没有部署所需的账号与鉴权，请勿直接暴露到公网。

停止开发服务后，可自行运行：

```sh
npm run build
npm run test
npm run e2e
npm run demo
```
